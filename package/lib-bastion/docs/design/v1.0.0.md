# Bastion V1 

## Concept
Bastion is a lightweight **Python library** for managing data pipeline ecosystems.
It provides a unified domain model for `Digital assets`, `Pipeline`, `Execution`, `Runtime`, `Execution history`, `Execution quality`, allowing any pipeline or workflow to be observable, controllable and maintainable.
> In short: Bastion manages the lifecycle of data pipelines.

## Motivation
Modern data platforms gradually become difficult to maintain.
Typical problems include:
- Nobody knows how many pipelines exist an wether its still running.
- Data quality is inconsistent and difficult to observe.
- Execution history is scattered across different systems.
- Different runtimes (Python, Glue, Lambda...) cannot be managed consistently.

## Design Principles

### 1. Asset 
The primary concern of Bastion is the data asset.
Pipelines exist only to update assets.
Asset is logical, not physical.
Aseet describe What the data is not where the data lives.

### 2. Runtime Agnostic
Bastion does not care whether a pipeline is executed by Local Python or AWS Glue etc. Every runtime is treated equally.

### 3. Metadata Only
Bastion never stores business data, but only manages metadata.
Examples include:
- Asset definitions
- Pipeline definitions
- Execution history
- Events
- Quality reports

### 4. One Responsibility
Every domain object answers exactly one question.
- `Asset`： What data do we care?
- `Pipeline`： How an Asset update / create?
- `Runtime`： Who executes a Pipeline?
- `Run`： What happened during one execution?
- `Quality`：Was the Run healthy?
- `Event`： What happened during the Run?
- `...`

## Core Data Model

### Asset
Asset represents **what** we care about as a logical data asset.
Examples:
- Stock Daily
- Customer
- Orders
- News

### Pipeline
Defines **how** an Asset is updated.
Pipeline itself never runs.

### Runtime
Represents the execution capability. Runtime defines **who** executes a Pipeline.
Examples:
- Local Python
- Glue
- Lambda

### Run
Represents one execution of a Pipeline. Run records lifecycle information.
Examples:
- Started
- Running
- Failed
- Finished


### Quality
Represents the quality result generated by one Run.
Examples:
- Row count
- Duplicate count
- Null rate
- Schema changes

### Event
Represents something that happened during a Run.
Examples:
- Started
- Retry
- Warning
- Failed
- Finished

### No Goals
Bastion will NOT:
- Execute SQL
- Read CSV
- Process data
- Replace Spark
- Replace Polars
- Replace Airflow
- Replace dbt
Those responsibilities belong to runtimes.

### Extra design pattern
- All timestamps stored by Bastion MUST be timezone-aware UTC datetimes.
