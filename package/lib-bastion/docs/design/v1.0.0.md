# Bastion V1 — 设计规范

## 是什么

轻量级 Python 库，管理数据资产生命周期的元数据。
**只管元数据，不碰业务数据。**

---

## 架构分层

```
┌─────────────────────────────────────────────────────────┐
│  Control（驱动层）— 有行为，驱动执行                      │
│      Hub  /  Compute                                      │
├─────────────────────────────────────────────────────────┤
│  Domain（领域层）— 领域结构 + IStore 接口定义              │
│      Asset / Bridge / Run / Quality / Event / IStore    │
├─────────────────────────────────────────────────────────┤
│  Infrastructure（基础设施层）— 提供能力与外部接入          │
│      InMemoryStore / SQLiteStore / DynamoStore / OSSStore│
│      AwsCredentials / AliyunCredentials                 │
│      IBastionModel / IBastionClock / Logger             │
└─────────────────────────────────────────────────────────┘
```

**注意**：
- `IStore` 是 Port，接口定义在 Domain 层，实现在 Infrastructure 层
- `Run` 持有完整状态机，Domain 层的约束是不含网络/IO/业务逻辑，而非不含任何行为
- `Hub` 自己**永远不产生数据**，只查询、只转发执行指令

---

## 四条设计原则

1. **Asset 第一** — Bridge 存在的唯一目的是更新 Asset
2. **Compute 统一** — Local Python / AWS Glue / Lambda / 阿里云 FC，对 Hub 暴露同一个接口
3. **Metadata Only** — 只记录"发生了什么"，不存业务数据
4. **One Responsibility** — 每个 domain object 只回答一个问题

---

## Domain Objects

| 对象 | 回答的问题 | 子类 |
|------|-----------|------|
| `Asset` | 我们关心什么数据？ | `LocalAsset` / `S3Asset` / `OSSAsset` |
| `Bridge` | 谁负责更新哪些 Asset？ | 无（name 唯一，Compute 可选） |
| `Run` | 一次执行发生了什么？ | 无（通用状态机） |
| `Quality` | 这次 Run 健康吗？ | `RowCountQuality` / `NullRateQuality` / `SchemaChangeQuality` |
| `Event` | 执行过程中出现了什么事件？ | `RunStarted` / `RunSucceeded` / `RunFailed` / `Warning` |

---

## 标识设计

**强实体（业务可命名）以 `name` 为唯一键，不自动生成 id：**

| 强实体 | 主键 |
|--------|------|
| `Asset` | `name`（如 `"stock_daily"`） |
| `Bridge` | `name`（如 `"update_stock_daily"`） |

**弱实体（系统生成，无需人类记忆）保留自动 id：**

| 弱实体 | 主键 | 外键 |
|--------|------|------|
| `Run` | `id`（`run-xxxx`） | `bridge_name: str` |
| `Event` | `id` | `run_id: str` |
| `Quality` | `id` | `run_id: str` |

---

## Bridge — 注册单元

Bridge 是 Hub 的注册单元，将一个（可选的）Compute 与一组 Asset 绑定。

```
Bridge(name, compute=None, assets=[])
  ├── name: str               ← 唯一键，业务可读
  ├── compute: Compute | None ← 有 → 主动执行；无 → 仅被动 DuckDB 扫描
  └── assets: list[Asset]     ← 此 Bridge 负责更新的 Asset（一或多个）
```

**约束**：
- 一个 Compute 可更新多个 Asset（一对多）
- 一个 Asset 只能由一个 Compute 更新（多步骤编排是 SFN/Airflow 的职责，不在 Bastion 范围内）
- `hub.register(asset)` 是语法糖，内部自动包为 `Bridge(name=asset.name, assets=[asset])`

---

## Compute — 统一接口

Compute 描述"如何执行"，与存储后端解耦：

```
ComputeLike (Protocol)
    └── execute(run, store) → None    ← Hub 调用的唯一入口

BaseCompute
    ├── execute(run, store)           ← 子类 override
    ├── start(run, store)             ← 状态机：PENDING → RUNNING
    ├── finish(run, store)            ← 状态机：RUNNING → SUCCEEDED
    ├── fail(run, store, error)       ← 状态机：RUNNING → FAILED
    ├── report(run, quality, store)   ← 写入 Quality
    └── attach(bridge_name, store)    ← 返回轻量 reporter（Mode 2 用）

LocalPythonCompute(fn)
    → execute() 同进程同步运行 fn()

GlueCompute(job_name, credentials: AwsCredentials)
    → execute() 提交 Glue Job，注入 BASTION_RUN_ID，轮询至完成（tenacity 重试）

LambdaCompute(function_name, credentials: AwsCredentials)
    → execute() 调 Lambda，等待响应

FCCompute(function_name, credentials: AliyunCredentials)
    → execute() 调 FC HTTP，等待响应
```

**远程 Compute 的 run_id 传递**：`execute()` 将 `run_id` 注入远程 Job 的环境变量（`BASTION_RUN_ID`），远程代码通过 `BaseCompute.attach()` 接入，只能调用 `report()`，不能改变 Run 状态。

## Hub

Hub 是控制/观测平面，不执行任何业务逻辑。Store 是唯一持久化来源，Hub 本身无状态。

```python
Hub(store: IStore)

# 主要方法
hub.register(bridge)               # upsert Bridge（含 Asset 定义）到 Store
hub.register(asset)                # 语法糖：自动包为 Bridge(name=asset.name, assets=[asset])
hub.run(bridge_name)               # 从 Store 加载 Bridge → 创建 Run → 调 Compute.execute()
hub.inspect(bridge_name)           # DuckDB 直查 Asset 数据位置（Compute=None 时的唯一入口）
hub.list_runs(bridge_name, limit)
hub.list_qualities(run_id)
hub.list_events(run_id)
```

---

## 类关系

```
Hub
  └──(持有)──▶ IStore
                 ├── Bridge（含 Asset 定义，持久化注册）
                 └── Run / Quality / Event

Bridge
  ├── name: str
  ├── compute: Compute | None
  └── assets: list[Asset]

Run
  ├── id: str          (run-xxxx)
  └── bridge_name: str

Quality / Event
  └── run_id: str
```

## 三种使用模式

### Mode 1 — Hub 驱动（Fortress ECS 场景）

Hub 和 Compute 同在 ECS，Hub 全权管理执行生命周期。Bridge 定义持久化到 Store，无需每次重建。

```python
hub = Hub(store=SQLiteStore("bastion.db"))

# 首次部署时注册一次，后续直接 run
hub.register(
    Bridge(
        name="update_stock_daily",
        compute=LocalPythonCompute(fn=fetch_stock_daily),
        assets=[
            OSSAsset(
                name="stock_daily",
                bucket="fortress-prod",
                prefix="market/stock/daily/",
                credentials=AliyunCredentials(),
            )
        ],
    )
)

run = hub.run("update_stock_daily")
assert run.status == RunStatus.SUCCEEDED
```

### Mode 2 — Compute 自报（去中心化）

Compute 进程独立运行，事后 Hub 查询。适合各 Compute 分布在不同基础设施的场景。

```python
# Glue Job / FC 函数 / 本地脚本内部
reporter = BaseCompute.attach(
    bridge_name="update_stock_daily",
    store=DynamoStore(table="bastion", credentials=AwsCredentials()),
)
with reporter:
    data = do_etl()
    reporter.report(RowCountQuality(count=len(data)))
# __exit__ 自动调 finish() 或 fail()

# 观测端（独立进程）
hub = Hub(store=DynamoStore(table="bastion", credentials=AwsCredentials()))
hub.list_runs("update_stock_daily", limit=30)
hub.list_qualities(run_id="run-xxxx")
```

### Mode 3 — 被动检查（Compute 零配合）

Bridge 不含 Compute，Hub 用 DuckDB 直接扫描 Asset 数据位置。

```python
hub = Hub(store=SQLiteStore("bastion.db"))

hub.register(
    Bridge(
        name="stock_daily_monitor",
        assets=[
            S3Asset(
                name="stock_daily",
                bucket="fortress-prod",
                prefix="market/stock/daily/",
                credentials=AwsCredentials(),
            )
        ],
    )
)

result = hub.inspect("stock_daily_monitor")
# → {"last_modified": "...", "row_count": 8420, "schema": {...}}
```

DuckDB 通过 `httpfs` 扩展原生读取 S3，OSS 使用 S3 兼容模式。

## Credential 设计

**原则：credential 属于需要网络访问的组件，Hub 自身不持有任何 credential。**

| 组件 | Credential 类型 |
|------|----------------|
| `GlueCompute` | `AwsCredentials` |
| `LambdaCompute` | `AwsCredentials` |
| `DynamoStore` | `AwsCredentials` |
| `S3Asset` | `AwsCredentials` |
| `FCCompute` | `AliyunCredentials` |
| `OSSStore` | `AliyunCredentials` |
| `OSSAsset` | `AliyunCredentials` |
| `LocalPythonCompute` / `SQLiteStore` / `LocalAsset` | 无（本地访问） |
| `Hub` / `Bridge` / `Run` / `Quality` / `Event` | 无（永远不接触网络） |

`AwsCredentials` / `AliyunCredentials` 均支持空 key（使用 IAM Role / 环境变量 / ECS Metadata）。  
由 `pydantic-settings` 统一处理优先级：显式传参 > 环境变量 > `.env` 文件 > 平台默认。

## 最小闭环目标（V1 里程碑一）

```python
from bastion import LocalPythonCompute, Bridge, OSSAsset, InMemoryStore, Hub, RunStatus

hub = Hub(store=InMemoryStore())

hub.register(
    Bridge(
        name="test",
        compute=LocalPythonCompute(fn=lambda: None),
        assets=[OSSAsset(name="my_asset", bucket="my-bucket", prefix="data/stock/daily/")],
    )
)

run = hub.run("test")
assert run.status == RunStatus.SUCCEEDED
```

**达到闭环的步骤（按顺序）：**

1. `Run`：`workflow_id` → `bridge_name: str`，完成状态机
2. `Bridge`：新建，持有 `name / compute / assets`
3. `LocalPythonCompute`：实现 `execute(run, store)`，内部调 `start / fn() / finish`
4. `InMemoryStore`：实现 `IStore` 的 `save / get / list`，同时存 Bridge 定义
5. `Hub`：实现 `register / run / list_runs / list_qualities`
6. `bastion/__init__.py`：暴露以上所有

`GlueCompute / FCCompute / LambdaCompute / DuckDB inspect` 在闭环跑通后按需叠加。

## 设计约束

- 所有时间戳：timezone-aware UTC datetime，不得使用 naive datetime
- `BaseEvent` 不可变（frozen dataclass 或等价方式）
- **强实体（Bridge / Asset）以 `name` 为唯一键**，Store 按 name upsert，不自动生成 id
- **弱实体（Run / Event / Quality）以自动 id 为键**，格式 `{prefix}-{hex}`，由 `IBastionModel` 生成
- `Hub` 不持有任何 credential，所有网络访问委托给 Store / Compute / Asset
- `BaseCompute.attach()` 返回的 reporter 只允许调用 `report()`，不得改变 Run 状态
- 多步骤编排（一个 Asset 由多个 Compute 更新）不在 Bastion 范围内，交由 SFN / Airflow 处理
