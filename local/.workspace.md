# local/ — Local Runtime Workspace

## What is this?

The machine-local working area of `app-fortress`. It holds runtime data:
secrets, logs, and data files that the app reads and writes while running.
It is **not source code**.

Almost everything here is git-ignored (see the repo `.gitignore`). Only
`.gitkeep` and this file are tracked. Paths are relative to the app root
(`./local/...`).

## Layout

| Path | Purpose |
|------|---------|
| `.auth/` | Secret key files (`node.key`, `mcphost.key`), created by `fortress auth init`. **Never read, print, or commit them.** |
| `.logs/` | Log output. `service/` has one log per service (node, mcphost, machine). `source/` has logs per data source (e.g. nswvg, tushare). |
| `provision/` | **Input.** Raw files put here by hand (e.g. manual downloads) for a data source to ingest. Layout: `provision/source/<source>/<dataset>/`. |
| `store/` | **Working storage.** The default local file store (`FileStore`). Layout: `store/source/<source>/<dataset>/`. |
| `vault/` | **Final storage.** The default local vault (`LocalVault`). Layout: `vault/source/<source>/<dataset>/`. |

Current sources: `nswvg` (`psi_week`, `psi_year`) and `tushare` (`tradedates`).

## Data flow

`provision/` (raw input) → source code in `app/resource/source/` → `store/` / `vault/` (output).

## Notes for Claude

- Treat this folder as runtime state. Don't hand-edit data or logs, and don't add code here.
- Never open or expose anything in `.auth/`.
- The code that uses these paths:
  - `app/resource/source/_common/_source.py` (provision)
  - `app/resource/store/file/store.py` (store)
  - `app/resource/asset/local/vault.py` (vault)
  - `app/setting/service.py` (logs)
